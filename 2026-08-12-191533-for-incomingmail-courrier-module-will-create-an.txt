● Done. Here's what was built.

  The feature

  A "Compléter avec l'IA" button in the header of the Informations du courrier
  section of IncomingMailForm. It reads the attached document and fills in
  sender, description, is_registered and has_acknowledgment.

  Pipeline: text is extracted locally first (reusing the existing AttachmentOcr
  — pdftotext for native PDFs, pdftoppm + Tesseract for scans), which is far
  cheaper than uploading the file. Only when nothing readable comes out is the
  file itself sent to the model.

  File sources, in order: the pending upload → the attachment already stored on
  the record (edit page) → the IMAP message (Inbox flow, streamed to a temp file
  and deleted afterwards).

  Blocked: the API key is wrong

  I could not complete a real end-to-end call. OPENAI_API_KEY in your .env holds
  an Anthropic key (sk-ant-api...), so OpenAI returns 401 Incorrect API key 
  provided. I retried through the anthropic provider using that same key to
  validate the wiring, and got InsufficientCreditsException — the key reaches
  Anthropic but has no quota.

  So the request construction, schema and response handling are exercised up to
  the provider boundary, but the model's actual extraction quality on your PDFs
  is unverified. Put a real sk-... key in OPENAI_API_KEY and it should work
  as-is.

  What I did verify on data/*.pdf

  - 195633_2.pdf — text layer, 828 chars extracted by pdftotext.
  - 195629_...-0004.pdf — a scan with no text layer; Tesseract OCR'd it to 1354
  chars, cleanly capturing OBJET : Demande de permis d'urbanisme - Réception 
  d'un dossier and the SPW sender. That's exactly the input the agent needs, so
  the hard half of the pipeline is proven on your real mail.

  Tests

  6 new tests in IncomingMailAiCompletionTest.php using
  IncomingMailAgent::fake() and a small committed PDF fixture (data/ is
  gitignored, so I generated a self-contained one). They cover the text path,
  the document fallback, the unreadable-format error, form filling, the no-file
  warning, and not clobbering what the user already typed.

  Full Courrier suite: 304 passed. Pint and PHPStan clean.

  One thing worth flagging: I initially keyed the section to target the action
  in tests, which silently broke assertFormFieldExists in
  IncomingMailReferenceNumberFormTest — ->key() prefixes every descendant
  field's lookup key. Fixed by wrapping only the action in a keyed Group, and
  recorded as a rule in .ai/rules/filament.md.
